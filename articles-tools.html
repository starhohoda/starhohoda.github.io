B01｜Google AI Studio 網站實作

透過 Google AI Studio 等開發輔助環境，使用者可以用結構化的文字規格描述網站需求，快速建立可互動的網頁原型，並進一步檢查版面與導覽體驗。（本單元為功能概覽與操作規劃）

核心操作重點

  1. 使用 AI 描述網站需求：預先整理好品牌定位、頁面結構、色彩變數與導覽階層，讓建置方向清楚明確。
  2. 建立網頁原型：分階段確認頁首、主視覺、內容卡片與頁尾，優先確保結構完整與文字清晰可讀。
  3. 檢查導覽與視覺設計：實際點擊各個分頁連結、手機版漢堡選單與子分類展開按鈕，確認沒有遮擋或失效連結。
  4. 區分預覽、原始碼匯出與正式發布：開發環境中的即時預覽僅供測試；若要長期公開瀏覽，需將靜態 HTML/CSS/JS 檔案匯出並部署至靜態網站託管服務。
✦ 操作規劃與環境提醒（功能概覽／待實測）

注意事項：預覽環境可能預設採用前端框架（如 React + Vite）。若目標是部署至純靜態空間，應同步確認獨立的 HTML、CSS 與 JavaScript 檔案結構是否完整，並檢查所有相對路徑與圖片素材是否能獨立載入。

B02｜ChatGPT 與 Gemini 工具比較方法

面對多種對話式 AI 工具時，若每次輸入不同的問題，很難判斷哪一個工具較適合自己的工作流程。建立一致的比較方法，才能獲得有參考價值的觀察紀錄。（本單元為比較方法規劃，待實測）

核心操作重點

  1. 為什麼需要使用相同任務比較工具：在不同工具中輸入完全相同的提示語與背景資料，才能排除提問方式差異帶來的影響。
  2. 如何設定比較標準：可從「指令理解準確度」、「繁體中文語句自然度」、「格式遵循程度」與「是否需要多次修正」四個面向觀察。
  3. 如何記錄實際操作結果：保留原始提示語、首次回覆內容、追問修正次數與操作日期，建立可回顧的對照表。
  4. 避免未經測試就主觀宣稱優劣：工具表現會隨任務類型與版本更新而變化，應根據實際測試紀錄描述適用情境，不作誇大定論。
✦ 工具比較紀錄表設計（操作規劃／待實測）

建議紀錄欄位：【測試日期】、【任務主題（如：300字會議摘要）】、【輸入提示語】、【工具 A 輸出觀察】、【工具 B 輸出觀察】、【人工修正項目】。目前本項目為方法規劃示範，尚未填入特定版本之實測結論。

B03｜NotebookLM 資料整理應用

當手邊有多份講義、研究筆記或長篇報告需要整理時，文件型 AI 工具能協助根據上傳的資料進行摘要與問答，降低跨文件查找的時間成本。（本單元為功能概覽與操作規劃）

核心操作重點

  1. 文件型 AI 工具的應用情境：適合用於整理公開講義、專案參考資料、讀書筆記彙整與長篇文件重點提取。
  2. 匯入資料前需要注意的事項：上傳前務必先檢查檔案內容，移除個人隱私資訊、內部機密數據或未經授權的文件。
  3. 如何根據資料提出問題：明確要求工具「僅根據已上傳的來源文件回答」，並可指定依章節或主題分類列出重點。
  4. 檢查整理結果與來源的一致性：善用工具提供的段落引用標記，點開原始段落核對摘要是否準確反映原意。
✦ 來源導向提問示範（功能概覽／待實測）

提問範例：「請根據我上傳的這份教學手冊，整理出初學者最需要注意的 5 個操作步驟，並在每一點後方標註對應的原始章節名稱；若文件內未提及的內容請勿自行補充。」
